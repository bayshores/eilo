## Product purpose

eïlo (pronounced AY-loh) is a proactive personal assistant for consistency and progress toward long-term goals. Several commitments can coexist across study, work and daily routines. It should give people clarity about what matters, help them resume after interruptions, and make progress rewarding.

- **Proactive initiation:** eïlo must reach out when a meaningful permitted signal, unresolved need or agreed follow-up warrants help, without requiring a fresh user message or a visit to the dashboard. Remembering and summarizing are supporting capabilities, not the whole product. The intended experience includes delivery while the user works elsewhere through an explicitly permitted surface; the opt-in desktop notification path is now implemented but actual delivery remains unverified and off by default. Responses, corrections, dismissal and breaks must inform later outreach.
- **Automatic upkeep:** normal conversation and explicitly permitted activity should supply the information used to create, organize and reconcile commitments and progress. Routine task forms and manual completion tracking must not become the user's job. The user explicitly requested optional direct management controls; these complement conversation when a correction is easier to make directly. Optional widget personalization is a separate concern.
- **Context with uncertainty:** assess activity against current goals and conversation. An app name or page visit is not proof of distraction, intent, completion, or a particular solution. Fine-grained problem/solution tracking is not required for the current concept.
- **Agency:** accept explanations, corrections, legitimate breaks and changed goals. Do not infer permission for monitoring, external actions or restrictions from a product discussion. Rigid schedules, permanent productive/unproductive app labels, and automatic blocking are not the chosen approach.
- **Motivation and independence:** encourage starting, returning to and following through on the user's own commitments. Keep feedback grounded in supported progress. Unsolicited preparation plans, strategies and work instructions are outside the default role; the user chooses how to do the work. Psychology and HCI research inform hypotheses and do not prove eïlo's effectiveness. Success is independent follow-through, not time spent obeying or talking to the assistant.
- **Continuity:** important goals, corrections and conversation state should remain coherent across sessions. Cross-device continuity is a desired experience, not an established implementation result.

## Autonomy: implemented scope and remaining gap

Sean's direction is automatic upkeep through conversation plus permitted activity, rather than requiring the user to operate a tracker. The first increment now maintains a bounded local journal of admitted approved-site observations, updates Home without another status report, and allows selective check-ins through the existing event lane. Adjacent valid samples support an observed duration; unknown/unshared intervals, long gaps and restarts do not accumulate time. A model can optionally associate the current admitted observation with relevant open commitments; that association is tentative and does not change task progress.

Recent multi-session summaries remain local. Sending those new summaries to Luna for conversational/event context requires the separate explicit data-flow decision; it is not enabled. The existing event lane retains its previously disclosed, minimized origin/title input. No new site grants or collection were enabled during implementation.

Written updates use actual native generation callbacks and a one-at-a-time Home presentation queue. Final check-ins remain in native history; already presented updates are suppressed across reloads when browser storage is available. Speech recordings are transcribed locally after release/stop and inserted into an editable draft. The user chooses Send. Live speech partials, TTS and always-listening capture are not implemented.

**Remaining acceptance:** a real permitted trial must establish both automatic context upkeep and a warranted assistant-initiated check-in without a fresh user message or dashboard visit. It must also establish appropriate silence, correction and break handling. A useful summary visible only after returning to Home is partial evidence, not the full proactive outcome. The current Chrome connection requires deliberate extension installation/grants and an enabled connection page left open. Sampling remains bounded by a short renewable lease; this is not an always-running desktop observer. Observed activity is not proof of attention, idle-aware working time, a solved problem or task completion. Automatic outcome updates require a reliable result signal from an authorized source; no such adapter is integrated yet. No real browsing trial or hardware-microphone test was performed in this increment.

## Selected design direction

- Desktop proportions, a neutral dark base, and readable information about multiple commitments.
- Home is composed of optional, content-specific widgets. A connected-goals view can be one widget; repeating the same node composition everywhere was rejected.
- Floating, rounded left navigation with the account menu at the bottom. A quiet cue reveals the hidden navigation; Home reclaims its space when it closes.
- Direct widget arrangement and corner resizing, with a visible hold cue, live reflow, cancellation/Undo, and background-click exit from editing. Extra views are available through More widgets instead of making Home a long scrolling page.
- **Typography B is selected: IBM Plex Sans**, with medium-weight headings, restrained tracking and aligned time numerals. See [the typography implementation](prototypes/widget-home/typography.css).
- Avoid decorative thin separators, olive green, colored edge stripes, slanted progress blocks, redundant small labels and the rejected textured/staged treatments. Functional relationship connectors are still allowed.
- Wallpaper and simulated Mac surroundings were for presenting mockup images. The running interface uses the actual host window.
- Iterate through small, concrete visual decisions together. The user should not have to supply specialist design vocabulary or diagnose every design problem.

## What exists and what remains open

The Hermes-backed service in `app/` now serves the selected widget Home at `/home/`, using the canonical interface source in `prototypes/widget-home/`. The same source also runs as an independent sample-data preview; `/workspace` retains the earlier task controls. Hermes is a provisional foundation; the selected early model route is exact `gpt-5.6-luna` through an isolated Codex subscription sign-in. Existing checks are scoped evidence, not proof of the entire intended experience.

Connected Home displays native messages, pending receipts, saved commitments and supported progress counts. It can send ordinary conversation and recover a saved publication. Its layout is independent of task content; a one-time transfer can preserve the arrangement from the standalone preview. The standalone preview still uses fixtures. Current activity observations cannot themselves complete tasks. Local speech input and streamed written updates are now available in connected Home. A local Electron development bundle now supplies the desktop lifecycle; reliable outcome reconciliation, standalone distribution and cross-device behavior remain open work. Speech uses the same conversation after the user sends the reviewed transcript; no paid speech route is introduced.

Nebius/hackathon use is a later decision with separate model, billing and participation requirements. Recheck current rules and spending controls before acting; a past credit balance is not a spending guarantee.

Remaining design work includes richer day context, supported goal relationships and motivating progress. The first integration must display only information the backend actually supplies: no invented schedules, relationship edges or practice streaks. Evaluate the core loop first: discuss several commitments, see the saved state, correct a misunderstanding, and return to the same conversation.
